# Governance Engine v0.5 Release Notes

## What this release establishes

- 30/30 MAS operational requirement definitions in `requirements/mas.yaml`.
- 30/30 MAS Test of Design and Test of Operating Effectiveness procedures in the governed workbook.
- Executable MAS test catalogue and Control Testing Brain integration.
- 30-case diagnostic evaluation corpus with 15 real-evidence repository fixtures and 15 synthetic boundary cases.
- 5 real-evidence Full cases so the upper sufficiency boundary is measurable on non-synthetic evidence.
- Exact active-corpus hash in `eval/active_set.json`.
- Historical score files retained under `eval/history/`; only a score matching the active corpus hash may inform current readiness.
- v0.5 status reports `INCONCLUSIVE` until the new corpus is freshly scored. This is intentional: no stale v0.3 result is reused as a v0.5 claim.
- Majority-class baseline margin is now required by the release gate.

## Scoring protocol

Because the v0.5 requirement set and corpus both changed from v0.3/v0.4, the first model run against this release must be a `recalibration` run. It establishes the new baseline and does not claim improvement. Only after the corpus is frozen may subsequent assessor changes use `ratchet` mode.

Example:

```bash
python eval/score.py --version v0.5.0 --mode recalibration --set-name golden_30_mas_v2 --no-incumbent
```

Do not label the assessor promoted until the exact active corpus hash is scored and `governance/release_gate.py` returns `PASS`.
