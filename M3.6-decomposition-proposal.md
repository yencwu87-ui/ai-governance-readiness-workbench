# M3.6 — proposed element decomposition (draft for argument, not for merging)

This is a proposal to replace both existing decompositions of M3.6. It is a second-line
judgement about what the requirement means, which is yours to make — I am drafting it so there
is something specific to disagree with.

## Why replace either

**The current three** (`requirements/mas.yaml`) read:

- e1 — Approved evaluation and independent-validation criteria define scope, methods and thresholds
- e2 — Independent validation responsibilities and separation from development are defined
- e3 — Limitations, conditions, residual risk and re-validation triggers are documented

All three are design-side: *defined*, *defined*, *documented*. None requires that validation
happened, on the deployed version, before go-live. A well-written policy with no validation
behind it satisfies all three, and an assessor judging against them would be right to say so.
For a control whose whole point is that someone who did not build the model actually challenged
it, that is the wrong shape.

This also explains the probe result without appealing to model bias. `e2` fired on all three
M3.6 documents because each describes an independent validation function — which is what `e2`
asks for. `e1` fired on none because the documents are validation *reports* citing criteria,
not evidence that criteria were *approved*. The model may have been reading correctly against a
requirement that had drifted.

**The thirteen** (`eval/corpus/M3.6/LABELS.md`) are closer to the MAS expectation and carry real
operating tests — `e1` results for the specific model version, `e5d` the recorded date precedes
go-live with both dates evidenced. But `e3b`, `e4b`, `e5b`, `e5c`, `e5d` is accretion: elements
grown by amendment rather than derived. And thirteen dropdowns per control on a blind read is
the punitive shape that produced 47 accepts to 4 amends.

## Proposed seven

Flat ids. Each is one testable thing. Design and operation both represented, so a policy cannot
reach `full` and an operating record cannot be defeated by a missing framework.

| id | Element | Lane |
|---|---|---|
| e1 | Evaluation criteria, metrics and acceptance thresholds are approved before testing begins | design |
| e2 | Evaluation results exist for the deployed model version, measured on held-out data the developers did not train on | operation |
| e3 | Testing covers the conditions the model will meet — robustness, edge cases, adversarial behaviour, and performance across the populations the use case affects | operation |
| e4 | The validator did not build the model and does not report into the function that did, and the person signing the opinion is named | design + operation |
| e5 | A dated validation outcome is recorded against a named accountable person, and that date precedes production go-live | operation |
| e6 | The outcome states limitations, conditions of use and the residual risk accepted | operation |
| e7 | Re-validation triggers are defined — material change, version or vendor-pushed update, drift breach, data source change, incident, and a periodic cadence by materiality tier | design |

Merges from the thirteen: `e3`+`e3b`+`e4`+`e4b` collapse into `e4` (independence is one property
tested several ways). `e5`+`e5b`+`e5d` collapse into `e5` (a validation outcome that is undated,
unattributed or post-go-live fails the same element). `e5c` becomes `e6`. `e6` (proportionality)
is folded into `e7`'s tiering rather than standing alone, because on its own it is unfalsifiable
— every validation can be argued proportionate after the fact. `e8` (third-party models) is
dropped as a separate element and belongs in M3.7 or a third-party control, since it is a
different population, not a different test.

## What this costs

Seven radios on a blind read is still more than one. If reviewers start leaving them unset, the
`reviewer_unset` count in the compare block is where it shows, and that is the number to watch
rather than a reassurance that seven is fine.

Two elements are compound (`e3`, `e7` each list several things). That is deliberate — splitting
them gives twelve elements again — but it means a `partial` on either is ambiguous about which
part failed, and the challenge will have to carry that specificity instead.

## What I am not claiming

I have not read the AI MRM Paper or P017-2025 against this. These seven are derived from the
thirteen you already wrote plus the shape of the control, not from the source instruments — so
the `source` entry for M3.6 should stay `unchecked` until someone reconciles them. Fixing the
decomposition without fixing its provenance would move the problem rather than close it.
